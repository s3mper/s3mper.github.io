**1. 보안관제의 개념과 목적**

보안관제는 정보통신망과 정보시스템에서 발생하는 보안 위협을 **지속적으로 모니터링하고, 탐지·분석하여 대응하는 활동**입니다. 넓게는 침해사고 예방, 보안시스템 운영, 정보공유도 포함합니다.

| 보안 목표 | 의미 | 관제에서 확인하는 문제 |
|---|---|---|
| 기밀성 | 허가받은 사람만 정보에 접근 | 개인정보 유출, 비인가 접근 |
| 무결성 | 정보가 임의로 변경되지 않음 | 홈페이지 위·변조, 데이터 조작 |
| 가용성 | 필요한 때 서비스를 정상적으로 이용 | DDoS, 시스템 장애 |

자료가 제시하는 기본원칙은 다음 세 가지입니다.

- **무중단:** 24시간 365일 관제 수행
- **전문성:** 네트워크·시스템·공격기법·분석에 대한 전문지식 확보
- **정보공유:** 관계기관과 위협정보 및 대응정보 공유

**2. 보안관제 운영 형태와 구성**

| 운영 형태 | 특징 |
|---|---|
| 원격관제 | 외부 관제센터에서 고객사의 보안 이벤트를 분석 |
| 파견관제 | 전문인력이 고객사에 상주하며 관제 |
| 자체관제 | 조직이 관제시스템과 인력을 직접 구축·운영 |
| 하이브리드관제 | 원격관제와 파견관제를 결합 |
| 클라우드관제 | 클라우드 자원·서비스에서 발생하는 이벤트를 관제 |

관제는 **시스템과 조직이 함께 작동하는 구조**입니다.

- **시스템:** 보안장비·서버 등에서 로그 수집 → 저장·처리 → 통합 분석
- **관제인력:** 실시간 모니터링, 초동분석, 보고, 대응
- **침해대응 조직(CERT):** 침해 여부 상세 분석과 전문 대응
- **정보공유 조직:** 위협정보를 공유하고 공동 대응 지원

**3. 보안관제의 전체 업무 흐름**

관제체계는 먼저 환경을 분석하고, 절차와 역할을 정한 뒤 운영합니다.

| 단계 | 주요 활동 |
|---|---|
| 환경분석 | 네트워크·서버·애플리케이션·PC 현황, 과거 사고, 주요 위협 파악 |
| 체계수립 | 탐지정책, 대응절차, 조직별 역할, 보고체계 정의 |
| 운영 | 이벤트 모니터링, 분석·대응, 정책 개선, 결과 보고 |

실제 이벤트 처리는 다음과 같이 진행됩니다.

1. **탐지:** 보안장비·서버·클라우드 등에서 이상 이벤트 확인
2. **접수:** 티켓을 생성하고 담당자 지정
3. **초동분석:** 원본 로그·패킷·연관 로그·과거 이력 확인
4. **판단:** 정탐·오탐 및 침해 가능성 판단
5. **대응:** 정해진 권한과 절차에 따라 차단·담당자 이관 등 수행
6. **보고·종결:** 분석 근거, 조치 내용, 결과 기록
7. **개선:** 분석 결과를 탐지정책과 대응절차에 반영

**중요한 구분:** 공격 시도가 탐지되었다는 사실과 실제 침해가 성공했다는 사실은 별개입니다. 자료도 공격 성공 여부를 확인하기 위해 대상 시스템 담당자에게 확인·조치를 요청하는 절차를 설명합니다.

**4. 주요 보안솔루션과 역할**

| 솔루션 | 핵심 역할 | 관제 시 확인할 사항 |
|---|---|---|
| 방화벽(FW) | 정책에 따라 통신 허용·차단 | 출발지·목적지 IP, 포트, 허용·차단 이력 |
| IDS | 침입 의심 행위 탐지 | 탐지 패턴과 실제 패킷의 일치 여부 |
| IPS | 침입 탐지 및 차단 | 차단 결과와 정상 서비스 영향 |
| WAF | 웹 요청·응답 기반 공격 탐지·차단 | URL, 매개변수, 요청 내용, 응답 |
| Anti-DDoS | 서비스 거부 공격 탐지·대응 | 트래픽 급증, 공격 유형, 서비스 영향 |
| NAC | 단말 인증과 네트워크 접근 통제 | 비인가 단말, 보안정책 미준수 단말 |
| Anti-Virus | 악성코드 탐지·제거 | 감염 파일, 탐지 결과, 치료 여부 |
| 웹쉘 탐지 | 서버의 웹쉘 등 의심 파일 탐지 | 비인가 파일과 실행 흔적 |
| 정보유출 방지 | 중요정보의 외부 유출 통제 | 전송 대상·내용·경로 |
| DRM | 문서 사용 권한 통제 | 열람·편집·인쇄 권한 |
| 매체제어 | USB 등 외부매체 사용 통제 | 인가 여부와 사용 이력 |

장비 이름을 외우는 것보다 **어떤 데이터를 보고 무엇을 탐지하거나 통제하는지** 이해하는 것이 중요합니다.

**5. 탐지기술과 정·오탐 분석**

| 탐지 방식 | 원리 | 장점 | 한계 |
|---|---|---|---|
| 패턴 기반 | 알려진 공격 문자열·시그니처와 비교 | 알려진 공격을 빠르게 탐지 | 새로운 공격이나 변형에 한계 |
| 행위 기반 | 일반적인 사용 패턴과 다른 행위 식별 | 이상행위 발견에 유용 | 정상 행위도 이상으로 판단할 수 있음 |
| 상관분석 | 여러 장비·시스템의 이벤트를 연결 | 단일 로그로 알기 어려운 공격 흐름 파악 | 데이터 정규화와 분석 역량 필요 |

정·오탐 판단은 경보 이름만으로 결정하지 않고 다음 자료를 종합합니다.

- **원본 로그:** 실제 요청과 탐지 조건
- **패킷·페이로드:** 공격 의도가 드러나는 내용
- **자산 정보:** 대상 서비스와 취약점의 관련성
- **연관 로그:** 다른 보안장비·서버에서 확인되는 흔적
- **과거 대응 이력:** 동일하거나 유사한 이벤트의 처리 결과
- **외부 위협정보:** IP·URL 등의 평판

외부 평판 조회는 자료에서도 원본 데이터 분석을 보완하는 수단으로 소개됩니다.

**6. 티켓팅과 공격 유형 분석**

티켓팅은 경보를 접수한 뒤 분석·조치·종결까지 추적하는 과정입니다. 단순한 접수 기록이 아니라 **누가 어떤 근거로 판단하고 어떻게 처리했는지 남기는 업무**입니다.

티켓에는 다음 내용을 정리합니다.

| 항목 | 기록 내용 |
|---|---|
| 기본정보 | 탐지 시각, 탐지 장비, 위협명 |
| 통신정보 | 출발지·목적지 IP, 포트, URL 등 |
| 분석내용 | 원본 데이터, 정·오탐 판단 근거 |
| 대응내용 | 차단, 담당자 통보·이관, 확인 요청 |
| 결과 | 담당자 회신, 조치 결과, 종결 내용 |

자료의 대표 분석 사례는 다음과 같습니다.

- **관리자 페이지 접근:** 관리 기능에 대한 비정상 접근 시도 확인
- **RDP 접근:** 원격접속 서비스에 대한 무차별 대입 등 확인
- **디렉터리 트래버설:** 허용 범위를 벗어난 파일 접근 시도 확인
- **SQL Injection:** 입력값을 이용한 SQL 조작 시도 확인
- **악성코드 감염 의심:** 시스템 정보와 관련 흔적을 수집하여 분석

**7. 정책관리·예방활동·시스템 운영**

관제는 발생한 경보를 처리하는 업무 외에도 다음 활동을 포함합니다.

| 영역 | 주요 업무 |
|---|---|
| 탐지정책 관리 | 신규 패턴 개발, 오탐 수정, 불필요한 정책 정리 |
| 차단정책 관리 | 유해 IP·URL·메일주소 추출, 기존 차단 여부 확인, 적용·이력관리 |
| 침해예방 | 개인정보·관리자 페이지 노출, 악성코드·웹쉘, 신규 취약점 점검 |
| 정보공유 | 보안뉴스, 취약점 권고문, 대외기관 전파정보 공유 |
| 시스템 운영 | 장애 대응, 형상관리, 백업, 자산 현행화 |
| 훈련 | DDoS·해킹메일·침투 등 모의훈련과 결과 분석 |

정책 변경은 **검토 → 보고·승인 → 권한 확인 → 적용 → 이력관리 → 결과 보고** 순으로 관리합니다.

관제시스템 자체의 상태도 점검해야 합니다. 주요 점검 항목은 CPU·메모리·디스크·전원·프로세스, 세션 수, 로그 유실, 시간 동기화(NTP), 백업, 이중화 전환 상태 등입니다.

**8. ESM·SIEM·SOAR의 차이**

| 구분 | 중심 역할 | 자료에서 다루는 기능 |
|---|---|---|
| ESM | 보안장비 이벤트 통합관리 | 경보 모니터링, 사고접수·이관, 유해정보 관리 |
| SIEM | 다양한 로그의 수집·검색·상관분석 | 보안·서버·웹 접속 로그를 연결한 위협 분석 |
| SOAR | 대응 절차의 연계·자동화 | 플레이북 실행, 사례 관리, 솔루션 연동, 대응 기록 |

예를 들어 SIEM이 여러 로그를 연결하여 의심 활동을 발견하면, SOAR는 정해진 플레이북에 따라 추가정보 조회·담당자 전달·대응 등을 연결합니다.

**플레이북**은 특정 위협에 대해 수행할 분석·판단·대응 절차를 정의한 실행 흐름입니다. 자료는 플레이북을 개발한 뒤 **검증, 담당자 승인, 적용, 유효성 평가**를 거치도록 설명합니다. — pp. 90–91

**9. AI를 활용한 보안관제**

이 자료의 AI 보안은 주로 **AI를 이용해 위협 탐지와 관제업무를 개선하는 활용**을 의미합니다.

| 구성요소 | 역할 |
|---|---|
| SIEM | 로그 수집·저장·검색 및 위협 분석 |
| AI | 정·오탐 분류와 이상행위 탐지 지원 |
| SOAR | 분석 결과에 따른 대응 절차 실행 |
| 관제인력 | 분석 결과 검토, 판단, 피드백 제공 |

자료의 통합 예시는 다음 흐름입니다.

1. 보안장비·웹서버 등에서 로그 수집
2. 분석 대상 데이터를 AI에 전달
3. AI 분석 결과를 SIEM과 연계
4. 탐지된 위협을 SOAR 사례로 관리
5. 외부 위협정보와 원본 로그를 추가 분석
6. 플레이북과 API 연동을 통해 대응

AI 운영에는 데이터 수집·전처리뿐 아니라 **학습모델 생성, 검증, 분석 결과 피드백, 모델 이력관리**도 포함됩니다.

**10. 보고서 작성과 현장 투입 준비**

| 보고서 | 주요 내용 |
|---|---|
| 일일 관제보고서 | 탐지·대응 현황, 티켓 내역, 시스템 상태, 정책 변경, 예방활동 |
| 월간·분기 보고서 | 운영 실적, 위협 동향, 특이사항 |
| 연간 보고서 | 연간 실적과 고도화 방안 |
| 침해사고 분석보고서 | 사고 개요, 피해 자산, 시간대별 경과, 공격·피해 내용, 향후 대응 |
| 정책 변경 문서 | 변경 신청, 적용 내용, 변경 이력 |

현장에 투입되면 먼저 다음 사항을 파악해야 합니다.

- 네트워크 구성도와 보안장비 목록
- 관제 대상과 업무 범위
- 담당 부서·유지보수 업체·연락체계
- 대응 권한과 보고 절차
- 보고서 종류와 작성 기준

자료 전체에서 가장 강조되는 실무 역량은 **경보를 확인하는 능력보다, 근거를 수집해 판단하고 대응 결과를 다른 사람이 이해할 수 있게 기록하는 능력**입니다.
